01 / 10

What we achieved

TokMesh Lite can now express a categorical rule in YAML and enforce it against CSV rows. It also rejects a contract that declares the rule without listing any permitted values.

The new contract vocabulary

quality:
  - column: status
    rule: accepted_values
    values:
      - operating
      - suspended
      - closed

In plain language: the status column may contain only one of those three strings. A value such as unknown creates a validation finding.

Why this matters for a data product. The expectation is no longer trapped in prose or in someone’s memory. It travels with the product contract and can be checked by a person, a local command, or a future automated pipeline.

What TDD means

Test-Driven Development describes one missing behavior before implementing it. The failure becomes evidence that the test can see the missing capability; the smallest implementation then turns that same test green.

  1. NeedState the data-product expectation.
  2. TestObserve behavior through a public seam.
  3. REDConfirm failure for the expected reason.
  4. GREENAdd only enough Rust to satisfy it.
  5. VerifyRun formatting, linting, and all tests.

The public seams we tested

InterfaceWhat a caller getsWhy we test here
load_manifest(&path) YAML becomes a typed ProductManifest, or a useful error. Tests use the same loading path as the CLI.
validate_product(&manifest) A report about whether the contract itself is sensible. An empty accepted-values list is a contract problem.
validate_data(&manifest, &path) A report about whether CSV data obeys the contract. An unlisted row value is a dataset problem.

We did not test private helpers. Tests should survive an internal rewrite as long as the caller-visible promises remain true.

#[test]
fn data_validation_rejects_value_outside_accepted_values() {
    let directory =
        tempfile::tempdir().expect("temporary directory should be created");
    let manifest_path = directory.path().join("product.yaml");
    let data_path = directory.path().join("data.csv");

    std::fs::write(
        &manifest_path,
        r"
id: tokmesh.ng-lithium-sites
name: Nigeria Lithium Sites
version: 1.0.0
owner:
  country: Nigeria
  organization: TokMesh Learning Laboratory
data:
  format: csv
  schema:
    - name: site_id
      type: string
      required: true
    - name: status
      type: string
      required: true
quality:
  - column: status
    rule: accepted_values
    values:
      - operating
      - suspended
      - closed
sovereignty:
  classification: national
  allowed_countries:
    - Nigeria
",
    )
    .expect("manifest fixture should be written");

    std::fs::write(
        &data_path,
        "site_id,status\nNG-LI-000001,operating\nNG-LI-000002,unknown\n",
    )
    .expect("CSV fixture should be written");

    let manifest = load_manifest(&manifest_path).expect("manifest should parse");
    let report =
        validate_data(&manifest, &data_path).expect("CSV should be readable");

    assert_eq!(report.issues.len(), 1);
    assert_eq!(
        report.issues[0].code,
        "quality.accepted_values.rejected"
    );
    assert_eq!(report.issues[0].location, "row[3].status");
}

GREEN part A: teach the manifest model

pub struct QualityRule {
    pub column: String,
    pub rule: RuleType,
    #[serde(default)]
    pub minimum: Option<f64>,
    #[serde(default)]
    pub maximum: Option<f64>,
    #[serde(default)]
    pub values: Vec<String>,
}

#[serde(rename_all = "lowercase")]
pub enum RuleType {
    Unique,
    Range,
    #[serde(rename = "accepted_values")]
    AcceptedValues,
}

GREEN part B: enforce the rule for each row

RuleType::AcceptedValues => {
    if !rule.values.iter().any(|accepted| accepted == value) {
        report.error(
            "quality.accepted_values.rejected",
            &location,
            format!(
                "value '{value}' is not one of: {}",
                rule.values.join(", ")
            ),
        );
    }
}
Read this Rust aloud. Borrow each accepted value with .iter(); ask whether .any(...) equals the CSV value; negate that answer with !; report an issue when none match.

Where the behavior lives

One YAML rule crossed four files while preserving the two small validation interfaces used by callers.

src/product/manifest.rs Defines the typed vocabulary: values and AcceptedValues.
src/product/validate.rs Checks whether the declaration itself makes sense.
src/data/quality.rs Checks whether each non-empty, correctly typed CSV value obeys the declaration.
tests/validation.rs Specifies both promises through public interfaces.

Cargo command glossary

Cargo is Rust’s project tool. It downloads declared dependencies, compiles code, runs programs, executes tests, and coordinates other development checks.

CommandWhat it doesHow to read success
cargo run -- … Compiles the development build when needed, then runs TokMesh Lite. Everything after -- is passed to TokMesh rather than interpreted by Cargo. The program prints its report and returns exit code 0, 1, or 2.
cargo fmt Rewrites Rust files into the standard style chosen by rustfmt. This removes debates about spacing and line wrapping. Usually prints nothing. Files may be changed mechanically.
cargo fmt --check Checks formatting without rewriting files. Useful before a commit and in CI. No output and exit code 0 means everything is formatted.
cargo test Builds test targets and runs the complete suite: library, binary, integration, CLI, and documentation test harnesses. Every section ends with test result: ok.
cargo test --test validation NAME -- --exact Runs one named test from tests/validation.rs. The second -- sends --exact to Rust’s test runner. One test runs; the others are reported as filtered out.
cargo clippy Runs Rust-aware static analysis. Clippy finds suspicious, needlessly complex, or unidiomatic code beyond what compilation alone reports. It finishes without warnings or errors.
--all-targets Checks the library, executable, tests, examples, and benchmarks that exist in the package. No target is silently omitted from linting.
--all-features Enables every declared Cargo feature while checking. TokMesh Lite currently has no optional feature set, but the gate remains future-safe. All feature combinations represented by “all enabled” compile cleanly.
-- -D warnings Passes -D warnings to Clippy. “Deny warnings” makes any warning fail the command, preventing warning debt. Exit code 0 means there were no warnings.
cargo build --release Creates an optimized binary under target/release/. We will use this for million-row performance measurements. The release profile finishes successfully.

PhraseMeaning

Finished in 0.00sThe measured test execution was extremely quick; compilation time is reported separately.
